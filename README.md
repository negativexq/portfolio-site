# omerfkoc.dev

Portfolio for Ömer Faruk Koç — Next.js (App Router) + TypeScript + Tailwind
CSS, built around one rule: **the visible site and everything machine-facing
render from the same canonical data, never a second hand-maintained copy.**

## Development

```bash
npm install
npm run dev
```

Quality checks:

```bash
npm run lint
npx tsc --noEmit
npm test
npm run build
```

## Architecture

Content lives once, in `data/*.ts`, typed against `lib/content/types.ts`.
Everything else — pages, the Engineering Graph, the Markdown endpoints, the
JSON-LD — is a view over that data:

```
data/*.ts (canonical)
    │
    ├── app/*/page.tsx           human-facing pages
    ├── lib/graph/build-graph.ts Engineering Graph (nodes/edges, /graph)
    ├── lib/markdown/*           Markdown serializers → /*.md, /llms.txt
    ├── lib/seo/person.ts        Person/ProfilePage JSON-LD
    └── benchmarks/              measures whether the above actually helps
```

### Machine-readable layer

Alongside the normal pages, the site exposes plain-text/Markdown
representations for AI agents and other non-browser clients — no
JavaScript rendering required:

| Route | What it is |
|---|---|
| `/llms.txt` | Agent-discovery index — what the site is, where the other machine-readable resources are |
| `/resume.md` | Aggregated profile (experience + selected projects + skills + current focus) |
| `/projects.md` | Full project catalogue + the Go Reliability Labs supporting-work group |
| `/experience.md` | Professional experience |
| `/skills.md` | Technical skills by area |
| `/learning.md` | Current learning and engineering directions |

These are generated by pure serializers in `lib/markdown/*` — see
`lib/markdown/serializers.test.ts` for the guarantee that changing a
project/experience/skill/learning entry in `data/*.ts` changes the
corresponding `.md` output with no manual sync step.

`/projects`, `/experience`, `/learning` and `/resume` also serve the same
Markdown when requested with `Accept: text/markdown` (content negotiation
via `proxy.ts`, rewriting internally to the matching `.md` route — see
`lib/http/accept.ts` for the header parser). Normal browser navigation is
unaffected; each page also carries a small visible "View as Markdown" link.

Structured identity data (`lib/seo/person.ts`) renders a `ProfilePage` +
`Person` JSON-LD graph on the homepage, built from `data/profile.ts` and
`data/engineering-areas.ts`, with `sameAs` linking the canonical GitHub and
LinkedIn profiles for identity disambiguation.

### Engineering Graph

`/graph` renders an interactive, data-driven graph of experience, projects,
technologies, concepts, evidence and learning directions — built entirely
by `lib/graph/build-graph.ts` from `data/*.ts`, with integrity checks
(`lib/graph/validate-graph.ts`) asserted on every build. Nothing is added
to the graph by hand; a project/experience/learning item appears there
because it exists in the canonical data, not because a graph node was
authored separately.

### AI discoverability benchmark

`benchmarks/ai-discoverability/` measures whether the machine-readable
layer actually helps — discovery cost, token efficiency, retrieval recall,
answer accuracy, and response size, HTML vs. Markdown, plus an identity
resolution check — against a running instance of the site, not a mocked
one. See `benchmarks/ai-discoverability/README.md` for methodology and
documented limitations.

```bash
npm run dev                    # in one terminal
npm run benchmark:ai           # in another
npm run benchmark:identity
```

## Testing

Node's built-in test runner (`node --test`), zero test-framework
dependency — Node 22+ runs TypeScript directly.

```bash
npm test              # everything
npm run test:markdown   # Markdown serializers
npm run test:http       # Accept-header parser
npm run test:seo        # Person/ProfilePage JSON-LD
npm run test:benchmark  # benchmark suite's pure functions
```

## Project structure

| Path | Contents |
|---|---|
| `data/` | Canonical content — profile, experience, projects, engineering areas, learning, metrics, architectures |
| `lib/content/types.ts` | Shared types for everything in `data/` |
| `lib/graph/` | Engineering Graph builder + integrity validator |
| `lib/markdown/` | Markdown serializers backing `/*.md` and `/llms.txt` |
| `lib/http/` | `Accept` header parsing for content negotiation |
| `lib/seo/` | Person/ProfilePage JSON-LD builders |
| `app/` | Pages (App Router) and the `.md`/`.txt` route handlers |
| `proxy.ts` | Content negotiation: rewrites a human route to its `.md` sibling on `Accept: text/markdown` |
| `benchmarks/ai-discoverability/` | Measures the machine-readable layer against a running instance of the site |
| `docs/PORTFOLIO_REFERENCE.md` | Content/copy source of truth — positioning, status legend, what can and can't be claimed as current experience |
